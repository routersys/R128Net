Jan Kokemüller氏によるEBU R128およびITU-R BS.1770準拠のラウドネス測定ライブラリ[libebur128](https://github.com/jiixyj/libebur128)をC#へ完全移植したライブラリです。
測定はマネージドヒープを一切確保せずに動作するため、ガベージコレクタが解析の経路を観測しません。
状態は単一のネイティブ領域から供給し、主要な演算はunsafeなポインタで記述し、ライブラリ全体をNative AOT向けに注釈しています。
正しさはソースの読解ではなく、MSVCでビルドした原典Cが出力した基準データとの突合で確認しています。

## 概要

R128Netはlibebur128をC#へ移植しています。瞬時ラウドネス、短期ラウドネス、統合ラウドネス、ラウドネスレンジ、相対閾値、サンプルピーク、トゥルーピークの全てを提供し、ヒストグラム算法と、複数の測定インスタンスを一つの値へ集約する機能も備えます。

公開する面はモダンなC#です。音声は`ReadOnlySpan<short>`と`ReadOnlySpan<int>`と`ReadOnlySpan<float>`と`ReadOnlySpan<double>`で受け渡し、モードの集合は原典の含意関係を再現する`[Flags]`列挙型として表し、オプションは`init`アクセサを持つ`readonly record struct`とし、結果は単一の`LoudnessMeter`クラスのプロパティとして公開します。ポインタを用いる内部実装は公開しません。

状態は全て、生成時に`NativeMemory.AlignedAlloc`で確保する64バイト境界の単一領域が供給します。その領域の配置は専用の型の`Layout`メソッドに一度だけ記述します。ソースジェネレータがその署名を読んで必要量の照会と束縛の両方を生成するため、報告する必要量と実際の消費量が食い違いません。

原典のCは本リポジトリに同梱していません。`reference`配下の参照ハーネスがlibebur128を固定したコミットで取得してMSVCでビルドし、各段の内部状態を倍精度のまま書き出します。テストはその出力を読み込んでC#側の結果と突き合わせます。

## 導入方法

```sh
dotnet add package R128Net
```

1. チャネル数と標本化周波数と必要なモードを指定して`LoudnessMeter`を生成します。モードごとに処理時間を要するため、必要最小限の集合を指定してください。
2. インターリーブされた音声を`AddFrames`へ投入します。フレーム単位で割り切れる限り、任意の長さのバッファを受け付けます。
3. 結果はプロパティとして読み出します。測定の途中でも読み出せます。
4. テストを実行する場合は、先に`reference/build.bat`を実行して参照データを生成してください。libebur128を取得してMSVCでビルドし、`reference/data`へ書き出します。
5. 実行例のNative AOTバイナリを作る場合は`publish-aot.bat`を実行してください。

## 主な機能

### 1. ラウドネスの測定

BS.1770の前置フィルタは高域シェルビングと高域通過の縦続接続であり、原典と同じく単一の4次系へまとめて実装しています。ゲーティングブロックは400msの長さを100msずつ進めるため、2011年改訂が定める75パーセントの重複となります。

瞬時ラウドネスは直近400msを、短期ラウドネスは直近3秒を対象とします。統合ラウドネスは-70 LUFSの絶対ゲートを適用した後、ゲート前の平均から10 LU下の相対ゲートを適用します。ラウドネスレンジはEBU Tech 3342に従い、平均から20 dB下のゲートを通過した短期ブロックの第10百分位数と第95百分位数を取ります。`GetLoudnessOverWindow`は設定した最大窓までの任意の窓のラウドネスを返します。

### 2. ピークの測定

サンプルピークは絶対値が最大の標本を入力形式の全振幅値で除した値です。トゥルーピークは96 kHz未満で4倍、192 kHz未満で2倍に、49タップの多相FIR補間器を用いて過標本化し、192 kHz以上では信号をそのまま扱います。いずれも測定全体に対する値と、直近の`AddFrames`に対する値を取得できます。

原典は変換した入力を一つのバッファへ書き、補間した標本の全てを二つ目のバッファへ書き、そのバッファを別の走査でたどってピークを求めます。本実装はこの二つのバッファと二回の走査を融合により除去しています。格納した値は変化せずに読み戻されるだけであり、最大値は走査の順序に依存しないため、融合しても全ての結果が同一です。

### 3. ゲーティングとヒストグラム

チャネルの重みはBS.1770に従います。サラウンドの位置は1.41倍を、デュアルモノとして指定したチャネルは2倍を寄与し、未使用として指定したチャネルは処理を飛ばし、環状バッファへも書き込みません。

ヒストグラム算法はブロックのエネルギーを0.1 LU刻みの1000個のビンへ量子化するもので、`LoudnessModes.Histogram`で選択します。結果が量子化される代わりに、長時間の測定でも記憶域が有界になります。指定しない場合はブロックのエネルギーを個別に保持し、これが既定の動作であり原典と一致します。

### 4. 複数インスタンスの集約

`LoudnessMeter.GatedLoudness`と`LoudnessMeter.LoudnessRangeOf`は測定器の並びを受け取り、全ての素材を単一の測定器へ投入した場合と同じ値を返します。複数のファイルを一つの番組として測定する場合や、一つのファイルを複数のスレッドで測定する場合に用います。ヒストグラム算法を用いるかどうかは全ての測定器で一致している必要があります。

### 5. 無確保と状態領域

フィルタ後の環状バッファ、フィルタ状態、チャネル配置、ピークの配列、ヒストグラム、補間器の全てが、生成時に確保する単一の整列済みネイティブ領域に置かれます。`[StateLayout]`を付けた型は必要量を確保子について総称な`Layout`メソッドに一度だけ記述します。計測用の確保子で走らせれば記憶域に触れずに必要バイト数が求まり、束縛用の確保子で走らせれば実際の割り当てが行われます。ソースジェネレータはこの単一の署名から`GetRequiredBytes`と`Bind`を生成します。

ブロックエネルギーの履歴は既定ではネイティブ領域上で倍加により伸び、原典の実質無制限な履歴を再現します。`PreallocateHistory`を指定すると要求した最大履歴から一度だけ寸法を決めるため、以後の測定は一切の確保を行いません。

マネージドヒープを確保しないことは主張ではなく計測で示しています。`GC.GetAllocatedBytesForCurrentThread`は、4種の入力形式の`AddFrames`と、ラウドネスレンジが行う整列を含む全ての問合せにおいて、差分が0バイトであることを報告します。

### 6. 数値検証

テストはMSVCでビルドした原典Cが出力したデータと突き合わせます。libebur128の内部状態は不完全型であるため、ハーネスは`ebur128.c`を自身の翻訳単位へ取り込んで状態へ直接到達します。テストが強制する一致の水準を次に示します。

| 段階 | 一致 |
|---|---|
| 前置フィルタの係数、20種の標本化周波数 | ビット単位で一致 |
| フィルタ出力とフィルタ状態 | ビット単位で一致 |
| 無音時の減衰におけるフィルタ状態、40ブロック分 | ビット単位で一致 |
| 補間器の係数、2種の過標本化率 | ビット単位で一致 |
| ゲーティングブロックと短期ブロックのエネルギー | ビット単位で一致 |
| 統合ラウドネス、瞬時値、短期値、任意窓、相対閾値 | ビット単位で一致 |
| ラウドネスレンジ、履歴算法とヒストグラム算法の両方 | ビット単位で一致 |
| サンプルピークとトゥルーピーク、全体と直近の両方 | ビット単位で一致 |
| ヒストグラムのビン計数、各1000ビン | ビット単位で一致 |
| 3インスタンスにわたる集約 | ビット単位で一致 |

これらは8種の構成で成立します。ステレオ、5チャネルサラウンド、デュアルモノ、ヒストグラム算法、100ms境界に揃えたバッファ長と揃えないバッファ長、44100 Hz、96000 Hz、そして振幅が1e-310と1e-40と5e-324と厳密なゼロを巡回する敵対的な信号です。

超越関数は個別に計測しています。`Math.Tan`と`Math.Log`は、それぞれ20000点の標本において、MSVCのランタイムと厳密に同じ倍精度値を返します。`Math.Pow`は標本の千分の一未満において最終位で1だけ相違するため、ヒストグラムの境界表は実行時に計算せず埋め込んでいます。

テストは131件あり、その全てが通ります。

### 7. 性能

Windows 11上のIntel Core i7-1360Pにおいて、`x86-64-v3`を基準にNative AOTで発行し、全てのモードを有効にした状態で、48 kHzのステレオ音声30秒を解析した結果です。

| 量 | 値 |
|---|---|
| 実時間 | 245 ms |
| 実時間に対する倍率 | 120倍 |

費用はトゥルーピークが支配します。これに対して次の最適化を施していますが、いずれも出力はビット単位で不変です。

| 最適化 | 効果 |
|---|---|
| 遅延線を2倍長に複製し、巻き戻しの分岐を除去 | 下段と合わせて |
| フレーム2段展開により独立な依存鎖を倍化 | 上段と合わせて2.1倍 |
| 遅延線を拡張済みの倍精度で保持し、タップごとの変換を除去 | 1.5倍 |
| 副フィルタ1から3までを位相方向にベクトル化 | 1.09倍 |

各蓄積の鎖は原典の加算順序を保つ必要があるため、鎖そのものは短縮できません。4フレームへの展開は計測の上で棄却しました。蓄積器4本がベクトルレジスタの予算を超えるため、Native AOTでは13パーセント後退します。実行時コンパイルによる計測は逆の結果を示したため、判断はNative AOTの数値で行っています。

K特性フィルタはチャネル方向にベクトル化しています。各レーンが1チャネル分の演算を原典と同じ順序で行うため、ビット単位で厳密です。4チャネル以上で1.4倍から1.8倍を得ます。2チャネル向けのベクトル経路も実装しましたが、雑音床を超える利得が計測されなかったため削除しました。

## APIリファレンス

### 生成

```csharp
using R128Net;

using LoudnessMeter meter = new(channels: 2, sampleRate: 48000, LoudnessModes.All);
```

| メンバ | 説明 |
|---|---|
| `LoudnessMeter(int, int, LoudnessModes)` | 既定のオプションで測定器を生成します |
| `LoudnessMeter(int, int, LoudnessModes, in LoudnessMeterOptions)` | オプションを明示して測定器を生成します |
| `Channels`、`SampleRate`、`Modes` | 生成時に指定した構成 |
| `MaxWindowMilliseconds`、`MaxHistoryMilliseconds` | 現在の窓と履歴 |
| `Dispose` | ネイティブ状態を解放します |

`LoudnessModes`は原典の含意関係を再現します。`ShortTerm`は`Momentary`を、`Integrated`は`Momentary`を、`LoudnessRange`は`ShortTerm`を、`TruePeak`は`SamplePeak`をそれぞれ含みます。

### 音声の投入

```csharp
meter.AddFrames(interleaved);
```

| オーバーロード | 全振幅値 |
|---|---|
| `AddFrames(ReadOnlySpan<short>)` | 32768 |
| `AddFrames(ReadOnlySpan<int>)` | 2147483648 |
| `AddFrames(ReadOnlySpan<float>)` | 1.0 |
| `AddFrames(ReadOnlySpan<double>)` | 1.0 |

標本はチャネル方向にインターリーブします。渡す領域はフレーム単位で割り切れる必要があります。

### ラウドネス

| メンバ | 単位 | 必要なモード |
|---|---|---|
| `MomentaryLoudness` | LUFS | `Momentary` |
| `ShortTermLoudness` | LUFS | `ShortTerm` |
| `IntegratedLoudness` | LUFS | `Integrated` |
| `LoudnessRange` | LU | `LoudnessRange` |
| `RelativeThreshold` | LUFS | `Integrated` |
| `GetLoudnessOverWindow(long)` | LUFS | `Momentary` |
| `LoudnessMeter.GatedLoudness(ReadOnlySpan<LoudnessMeter>)` | LUFS | 全ての測定器の`Integrated` |
| `LoudnessMeter.LoudnessRangeOf(ReadOnlySpan<LoudnessMeter>)` | LU | 全ての測定器の`LoudnessRange` |

ラウドネスが負の無限大となる場合は、素材が無音であるか、全体が絶対ゲートを下回っていることを意味します。ラウドネスレンジが0となる場合は、ゲートを通過した短期ブロックが不足していることを意味します。

### ピーク

| メンバ | 必要なモード |
|---|---|
| `GetSamplePeak(int)` | `SamplePeak` |
| `GetPreviousSamplePeak(int)` | `SamplePeak` |
| `GetTruePeak(int)` | `TruePeak` |
| `GetPreviousTruePeak(int)` | `TruePeak` |

1.0が0 dBFSに相当するため、デシベルへの換算は`20 * log10(値)`です。名前に`Previous`を含むものは直近の`AddFrames`に対する値を返します。トゥルーピークがサンプルピークを下回る値を返すことはありません。

### チャネル

| メンバ | 説明 |
|---|---|
| `SetChannel(int, ChannelPosition)` | チャネルへ位置を割り当てます |
| `GetChannel(int)` | チャネルの位置を読み出します |

既定の配置は、4チャネルと5チャネルにはBS.1770の配置を割り当て、それ以外は先頭から順に左、右、中央、未使用、左サラウンド、右サラウンドを割り当てます。`ChannelPosition.DualMono`はモノラルの測定器の単一チャネルにのみ指定できます。

### オプション

| メンバ | 既定値 | 説明 |
|---|---|---|
| `MaxHistoryMilliseconds` | 4294967295 | 統合ラウドネスとラウドネスレンジが保持する履歴 |
| `PreallocateHistory` | `false` | 履歴を伸ばさず一度で寸法を決めます |
| `UseUpstreamWindowOverflow` | `false` | Windowsにおける原典の整数オーバフローを再現します |

## 制限事項

- ビット単位の一致はWindows x64上でMSVCによりビルドしたlibebur128に対して確認したものです。他のコンパイラ、他のランタイム、他のアーキテクチャは超越関数の丸めが異なる可能性があり、それらに対する一致は主張しません。
- ヒストグラムの境界表は1001個の要素のうち2個で原典と最終位が1だけ相違します。埋め込んでいる値が正しく丸めた側であり、MSVCの`pow`が正しく丸めていません。`pow`はIEEE 754において正しい丸めを要求されない関数です。相違はヒストグラム算法の内部に限られます。
- `LoudnessMeter`はスレッドセーフではありません。並行して測定する場合はスレッドごとに測定器を用意してください。集約の機能はその用途のために設けています。
- 前置フィルタが発散する標本化周波数は、原典が受理するのに対し、本実装は生成時に拒否します。3364 Hz以上は全て受理します。
- `ebur128_set_max_window`と`ebur128_change_parameters`は移植していません。いずれも音声バッファを確保し直すものであり、測定器を作り直すことで代替できます。
- 突合のテストには参照データが必要です。`reference/data`が存在しない場合、それらのテストは実行できません。
- `R128Net.Examples`配下の実行例はコンソールへ出力するためマネージドヒープを確保します。無確保の保証はライブラリに対するものです。

## 注意事項

- 処理の費用: トゥルーピークが最も高価であり、全体の大部分を占めます。モードの集合から外すことが測定を速くする最も効果的な手段です。サンプルピークとゲーティングはこれに比べて小さい費用です。
- 非正規化数の扱い: 原典はフィルタ処理の間、MXCSRレジスタのフラッシュトゥゼロビットを有効にします。.NETのランタイムは相当する機能を公開していないため、演算単位でフラッシュを模倣しています。この模倣は無音時の減衰における状態の遷移を原典と厳密に再現し、加えて、非正規化数の演算が無音時に招く50倍の速度低下も回避します。
- 測定器の再利用: 状態は生成時に一度だけ確保します。バッファごとに測定器を作ると意味がなくなり、ネイティブ領域の確保が再び生じます。
- 決定性: 測定は繰り返しても同一の結果を生み、`AddFrames`へ渡すバッファの長さにも依存しません。テストは同じ素材を1フレームずつ投入した場合と一括で投入した場合の結果をビット単位で比較しています。
- 状態の配置: `[StateLayout]`を付けた型は`IStateAllocator`について総称な`Layout`メソッドを公開する必要があります。ジェネレータは対応する引数列を持つ`GetRequiredBytes`と`Bind`を生成し、型が既に宣言している方は生成しません。
- Native AOT: ライブラリは`IsAotCompatible`を指定しており、トリムと単一ファイルとAOTの各アナライザが有効になります。`publish-aot.bat`は実行例を`win-x64`向けに発行し、ネイティブリンカのためMSVCツールセットを必要とします。加えてVisual Studioのインストーラのディレクトリを検索パスへ追加します。`vswhere.exe`を解決できない場合、AOTコンパイラのリンカ探索が失敗するためです。
- 参照データの再生成: `reference/build.bat`はlibebur128を`reference/ebur128-src`へ取得し、固定したコミットであることを検証してからビルドし、データを書き出します。取得先とビルド生成物はバージョン管理から除外しています。
